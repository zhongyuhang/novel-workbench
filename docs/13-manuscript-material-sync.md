# 13 正文与资料同步

审计时对照 `docs/release-1.0.0-plan.md` 的「正文与资料」和「生成闭环」，以及当时的代码。做法仍是在现有作品、记忆提案、质量问题和伏笔上补齐，不换技术栈，也不另起一套资料库。

下表的「动手前」是补齐之前的代码。后面一节写本轮实际补上的缺口。

## 本轮补齐

- 迁移 `0013_manuscript_material_sync` 接在 `0012_model_config_center` 之后。旧伏笔的三个时间文本为空。旧质量问题的分类是 `suspected`。旧故事线的明暗标记为空。
- 完整分析：作者点击分析，或章节状态第一次改为定稿。请求里的 `scope` 为 `full`。指定 `model_config_id` 就用那一份，否则用默认模型；还没有默认时，沿用最近一份已启用的外部模型。模拟分析不访问网络。
- 轻量检查：`scope` 为 `light`。只从本章抽关系、伏笔、设定补充和潜在冲突，不调用模型，也不重复插入同一条仍开放的候选。手动保存会请求一次。自动保存不会。
- 确认才写入正式实体、状态、事件、摘要、关系、伏笔或设定补充。潜在冲突在确认或标成有意矛盾时，只写质量问题，不改设定和正文。忽略和延后不写正式资料。
- 伏笔五个维度保持独立：`event_time_text`、`introduced_chapter_id`、`character_discovered_text`、`reader_revealed_text`、`status`（另有可选的 `payoff_chapter_id`）。
- 暗线用故事线上的 `thread_visibility=hidden`。它不替代原来的主线、支线、人物线类型。
- 影响分析按实体、关系、事件、伏笔或故事线列出仍关联着的对象，例如关系、状态、事件、章节、伏笔、故事线、场景和质量问题。

未确认的候选仍然不能进入正文，也不能进入正式设定。质量检查和影响分析都不自动改稿。
