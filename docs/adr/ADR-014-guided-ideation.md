# ADR-014：引导式创意、世界观与人物设计

## 状态

已采纳

## 背景

作品元信息、小说圣经、人物关系、故事线和统一模型调用都已经能用。缺的是作者从零或从已有设定出发，分步得到作品方向、世界设定和人物设计，并且在确认之前不写入正式资料。

记忆提案必须带源章节，从零创意时可能还没有章节。正文任务的采纳会写章节修订。这两条都不能直接拿来当设计候选。

## 决策

1. 不改 `0001`–`0013`。新迁移是 `0014_guided_ideation`。`novels` 增加可空文本 `core_conflict`。新增 `ideation_sessions` 和 `ideation_candidates`。旧作品的核心冲突为空，新表为空。
2. 一次会话属于一本作品，种类是引导式创意、世界观或人物。问题脚本放在服务里，按顺序回答。生成之前不调用模型。
3. 模型在创建会话时解析：显式 `model_config_id`，否则默认模型，再否则最近一份已启用的外部模型。配置 ID、模型标识和提示词版本记在会话上。同一次会话再次生成不再换模型。调用经 `app.ai.gateway` 和现有适配器。模拟模式不访问网络。
4. 候选状态是 `pending`、`accepted`、`rejected`、`deferred`。确认可以带修改后的内容。拒绝就是忽略。延后和忽略都不写正式资料。不使用「有意矛盾」，那个状态只留给正文与资料同步里的冲突。
5. 确认作品方向时，只写入非空字段：题材、文风备注、简介、核心冲突，以及全书大纲的一句话。大纲行保持或退回 `draft`。确认世界设定或人物卡时新建正式实体。确认关系时两端必须已经存在。确认人物弧线时新建草稿故事线，类型为 `character`。
6. 以上写入都不修改章节正文、字数或修订。生成和回答问题也不写这些正式行。
7. 上下文编译器在核心冲突非空时，把它放进作品硬规则。候选表不参与编译。
8. 作品包仍是原来的格式版本。`core_conflict` 缺省时按空导入。

## 不做

- 不把设计候选塞进必须有源章节的记忆提案。
- 不把大纲一句话或人物弧线直接标成已确认事实。
- 不新增正文任务类型，也不走会写正文的采纳。
- 不换技术栈，不引入向量库、多 Agent 或另一套模型客户端。

## 替代方案

- 复用记忆提案并改成章节可空：会放宽所有正文分析提案的约束，否决。
- 确认方向时把全书大纲标成已确认：会跳过现有的大纲确认，把候选直接变成硬约束，否决。
- 关系两端不存在时自动建人：作者还没确认那两张人物卡，却先写下关系，否决。

## 后果

旧库升级后可以继续写正文。核心冲突为空时，上下文与升级前一致。要去掉这两张表或这一列，用新的降级迁移，不改 `0014` 的升级历史。
