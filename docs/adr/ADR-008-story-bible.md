# ADR-008：小说圣经的关系、有效时间与字段级撤回

## 状态

已采纳（E3 / 阶段 D，2026-10-19）

## 背景

正式设定已经有实体、动态状态、事件、摘要和带证据的提案。缺口是：

- `entity_update` 接受时保存整份 `before`，撤回时整份写回。接受之后的手工修改会被盖掉。
- 没有人物关系表。档案 JSON 可以随便写一段关系，但没有两端、类型、故事时间和来源。
- 动态状态没有故事内生效区间。作者还没想好时间时，不能因此不能写作。
- 设定页把这些材料拆开，证据也不总是和档案放在一起。

任务书禁止用整份实体快照覆盖后续修改，也禁止为关系引入图数据库。

## 决策

1. 不改 `0001`–`0007`。从 `0008_story_bible` 起新增 `entity_relations`，并给 `entity_states` 增加可空的 `valid_from_text`、`valid_until_text`。旧状态行这两列为空。
2. 关系是有向的。两端都是同一作品里未删除的 `story_entities`，且不能是同一个实体。`relation_type` 必填。故事时间、故事线标签、来源章节、来源修订和证据都可以空。空故事时间可以保存。
3. `storyline` 只是关系上的可选标签，供设定页筛选。不建 `story_arcs`，也不把它当成外键。
4. 关系可以没有来源章节。填了章节就必须属于这本作品；没填修订号时，记下该章当时的 `revision`。
5. 动态状态的生效起止是两段可空文本，不是日期类型。手工记录和 `entity_state` 提案都可以不填。不填不拒绝请求，编译器也不编造时间。
6. 新的 `entity_update` 在接受时写入 `payload.field_changes`，只包含这次值真正变化的字段，以及该字段的前后值。撤回只改这些字段。
7. 若 `field_changes` 里任一字段的当前值已经不等于接受后的值，整次撤回失败，返回 `409`。不部分回滚，不删除这次写下的状态行，提案保持 `accepted`。
8. 没有 `field_changes` 的旧提案拒绝自动撤回。保留 `before` 只作查阅，不再用它覆盖实体。正式设定保持不动。
9. 撤回名称若会和现有设定重名，同样整次拒绝。
10. 设定页仍在右侧「设定」里。标题改为小说圣经，集中展示实体、关系、动态状态、事件、摘要和提案。筛选按实体、章节、关系故事线标签和状态。证据和来源章节留在条目上。
11. 上下文编译器在名称或别名已经命中某个实体时，带上连到该实体的关系。不扫描其他作品，不做图遍历。关系可以因为预算被排除，并写明原因；证据正文不静默截短。状态上有有效时间时，写进该实体的材料。

## 不做

- 不把参与者改成实体外键。事件仍用原来的文本列表。
- 不建人物知情范围，也不在提示里区分读者已知和人物已知。
- 不把有效时间重叠自动报成冲突。状态变化本身仍不是矛盾。
- 不新增关系类提案。关系由作者在圣经里记录。
- 不建向量库、图库，也不改 `0001`–`0007`。

## 替代方案

- 撤回时继续用整份 `before`：会盖掉接受之后的手工修改，和任务书冲突，否决。
- 只回滚没被后改的字段，被后改的字段跳过：一次撤回会留下半套旧值，作者看不出这次撤回到底动了什么，否决。
- 没有字段级记录时仍按整份快照撤回：旧数据同样会盖掉后来的修改，否决。
- 用图数据库存关系：第一阶段不需要，查询就是同一作品上的两端外键，否决。
- 故事时间用必填日期：作者经常还没有日历，会挡住记录和写作，否决。

## 后果

已接受、但只有整份 `before` 的设定更新不能再一键撤回。作者需要手工改回，或重新接受一份新提案。新接受的设定更新可以按字段撤回；后改过的字段会保住。旧库升级后关系表是空的，已有状态没有有效时间，正文修订号不变。
