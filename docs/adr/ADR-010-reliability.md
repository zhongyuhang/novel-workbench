# ADR-010：采纳事务、保存冲突与版本来源

## 状态

已采纳（E5 / 阶段 F 中的可靠性部分，2026-10-19）

## 背景

长篇写作里最容易丢稿的路径已经有基础：章节 `revision` 乐观锁、自动保存不写快照、AI 采纳在一次提交里写正文和任务决议、取消后迟到 token 不再写入。E5 要把这些路径收成同一套可验证的行为，并补上版本差异、恢复预览和版本来源。作品级导入导出包仍属于 E6。

## 决策

1. 不改 `0001`–`0009`。`0010_version_provenance` 只给 `chapter_versions` 增加可空的 `ai_task_id` 和 `repair_candidate_id`。SQLite 不能直接 ALTER 外键，这次用批量表重建，并保留原有主键、`(chapter_id, revision)` 唯一约束和 `change_source` 检查。旧快照的两个外键保持为空。删除任务或修复候选时外键是 `ON DELETE SET NULL`，版本行本身留下。
2. 手动保存、普通 AI 采纳和质量修复采纳共用同一套正文写入。`apply_accepted_candidate` 在一个数据库事务里校验当前修订、更新正文和字数、写入 `chapter_versions`、用条件更新认领 AI 任务决议或修复候选，并标记该章记忆过期。任一步失败都回滚，不留下半完成的正文、快照或决议。调用方不得在进入这个函数之前把决议或候选状态先提交。
3. 采纳前再核对任务快照里的 `target_revision`。它必须是整数，并且等于当前章节修订。只把请求里的修订号改成新值，不能把针对旧正文生成的候选写进去。选区缺失或出现多次时返回 `422 SELECTION_NOT_FOUND`，不写库。`replace_selection` 的选区为空时仍按既有确认替换整章。`append` 追加，`insert` 插在唯一选区之后。
4. 重复采纳同一任务，或两个请求同时采纳，只有一次能把 `resolution` 从空改成 `accepted`。另一次返回 `409 TASK_STATE` 或 `409 REVISION_CONFLICT`，正文里该候选只出现一次。质量修复同样用候选状态从 `proposed` 到 `accepted` 的条件更新认领；问题在同一事务里标为 `fixed`。修订已经变了则候选标为 `conflict`，正文保持较新的那一版。
5. 自动保存只更新 `chapters`，不产生 `chapter_versions`。手动保存、采纳、恢复和导入才写快照。冲突时编辑器保留本地草稿，读出服务器正文并排和逐行差异。载入服务器正文会替换编辑器。用本地草稿覆盖是一次 `save_kind=manual`，针对服务器当前修订，并留下快照。失败时正文留在编辑器里，非冲突错误提供重试。切章、回作品库和关闭页面前，未保存修改仍要确认。
6. 前端用递增的保存代次忽略迟到响应，避免旧的成功把修订号拨回去，或旧的 409 盖掉新的保存。真正防覆盖的仍是服务端修订锁。
7. AI 任务状态以数据库为准。SSE 只通知。流结束或中断后，前端用 `GET /api/v1/ai/tasks/{id}` 取回状态和已有候选。取消会立刻忽略后续 token；取消成功后再读一次任务，用库里的 `output_text` 覆盖本地片段。取消请求失败时重新读取任务：库里已经完成就显示那份候选，库里已取消则保持取消。已经结束的任务不能再被迟到 token 改写。超时、限流、模型不可用和格式错误只返回安全错误信息。日志继续脱敏，API Key、访问令牌和 JWT 不进日志。
8. 版本列表显示修订时间、`change_source`（`manual`、`ai_accepted`、`restore`、`import`）和来源。能关联时显示 AI 任务或质量修复候选。记忆分析不另加列，按 `memory_change_proposals.source_chapter_id` 与 `source_revision` 查询。`GET .../versions/{version_id}` 只读，返回纯文本和提案编号，不改变修订。`GET .../versions/diff` 比较两个版本，或把一侧写成 `current` 表示当前正文。差异是按行的纯文本，操作只有 `equal`、`insert`、`delete`。恢复前先看预览。恢复仍创建新修订，不删除中间版本。
9. 整库 SQLite 备份会带走正文、版本、来源外键、任务和记忆。E6 的作品包导入导出不在本阶段。`change_source=import` 仍保留给将来的作品包。

## 不做

- 不做作品级导出/导入包，不改现有 Markdown/TXT 导出的内容。
- 不把 SSE 缓冲写成第二份权威状态。
- 不新增 `change_source` 取值。质量修复采纳仍是 `ai_accepted`。
- 不引入向量库、图库或多 Agent。
- 空选区的整章替换语义保持不变，避免和现有确认文案分叉。

## 替代方案

- 采纳和修复各写各的事务：并发和失败回滚会对不齐，否决。
- 在版本行上再存记忆提案编号：提案已经按来源修订可查，多一列会在重新分析时过期，否决。
- 冲突时自动用本地草稿覆盖：那会把自动保存变成静默的新版本，否决。
- 用字符级 diff 或保留 Tiptap 标记的结构化 diff：恢复和采纳本来就按纯文本重建，先做行级差异就够作者判断，否决更重的实现。
