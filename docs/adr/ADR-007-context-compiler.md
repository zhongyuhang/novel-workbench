# ADR-007：ContextCompiler 的输入输出与快照保留

## 状态

已采纳（E2 / 阶段 C，2026-10-19）

## 背景

`context_builder.py` 已经在创建 AI 任务时组装一段字符串。模拟模型和外部模型走同一条路径，查询也限制在当前作品。缺口是：结果不可逐条解释，风格指南被标成可截断，已确认大纲还没有进入提示，任务详情也看不到当时用了什么。

ADR-006 把「正文变化时自动把已确认大纲标成 stale」留到编译器接入之前。这一条从本 ADR 起生效。

## 决策

1. 不另写一个平行编译器。`compile_context` 仍在 `backend/app/services/context_builder.py`。`assemble_context` 继续给旧的打包测试使用，并改成调用同一套预算函数。
2. 稳定输出是 Pydantic 模型 `ContextItem` 和 `CompiledContext`。`token_estimate` 与预算都是字符数，并在接口和文档里标明这是估算，不是分词器。
3. 创建任务必须调用编译器。编译抛出的领域错误原样返回。其他异常变成 `422 CONTEXT_COMPILE_FAILED`，不创建任务，也不改成空上下文再去生成。作品存在但没有设定时，编译成功，材料可以只有系统规则和本次指令。
4. 默认只纳入 `planning_counts_as_fact` 为真的作品大纲、当前章节大纲和场景卡片。草稿、过期、归档进入未纳入列表，排除原因写明它们不是事实。用户可以固定纳入一条草稿，条目会标成未确认，并且不改数据库里的大纲状态。
5. 作品硬规则、已确认大纲和场景卡片不可截断。预算放不下时保留全文并写入警告。可丢弃的材料先按优先级去掉。上一章等引用片段可以截短，但必须有警告。
6. 固定纳入和排除只存在于编译请求和这一次任务的快照里。编译预览 `POST /api/v1/ai/tasks/context/compile` 不写任务，也不写设定或大纲。
7. 快照继续放在 `ai_tasks.input_snapshot`，不新增 `0008` 表。生成器从这份快照读取 `prompt`，所以提示词全文要留下。单条材料副本上限 4000 字，整份 JSON 大约 18 万字以上就缩短副本，不缩短即将送给模型的提示词。快照随任务行保留，没有单独的过期作业。密钥和 `secret_ref` 不写入；指令里的密钥形状文本在落库前打码。
8. 旧快照没有 `compiler_version` 时，查询接口返回 `legacy=true` 和说明，不补造来源。
9. 章节正文修订变化时，沿用 `mark_chapter_memory_stale` 的三个调用点，把该章 `confirmed` 的章节大纲和场景卡片改为 `stale` 并增加规划修订号。不改大纲正文，不改作品级大纲，不增加章节正文修订。
10. 检索仍是名称、别名、有限 `LIKE` 和相邻章节。`LIKE` 不称作语义检索。故事线和卷大纲只留一个返回空列表的钩子。

## 不做

- 不建向量库、图库，也不做多 Agent。
- 不把编译结果写回设定库或大纲。
- 不改 `0001`–`0007`。
- 不在这一阶段做故事线、卷大纲、人物关系或质量修复候选。

## 替代方案

- 新建 `context_snapshots` 表：任务行上的 JSON 已经保存当时的提示词，再拆表要迁移和双写。体积用副本上限处理，否决。
- 预算不够就继续把硬规则截到 80 字：和 `docs/05` 以及任务书冲突，否决。
- 只存材料 ID，查看时再读当前设定：设定后来被改，任务当时用过的内容就丢了，否决。
- 编译失败时退回系统提示继续生成：作者会以为用了设定，否决。

## 后果

已有任务仍能打开。它们的上下文接口会说明没有条目级来源。新任务可以在生成前预览，也可以在任务上查看纳入、排除、警告和来源修订。正文采纳、取消和 `409` 的语义不变。
