## 实施总规则

每个阶段必须交付：代码、测试、运行命令、变更说明、验收记录。不得只提交静态页面或伪造 API 数据。外部模型尚未配置时，可以使用 mock provider，但界面必须明确标示 mock。

## M0：项目初始化与决策（先完成）

任务：
- 建立仓库目录和前后端基础工程。
- 增加 `.gitignore`、`.env.example`、格式化/类型检查配置。
- 记录 ADR-001 正文格式、ADR-002 数据库、ADR-003 AI 任务生命周期、ADR-004 认证、ADR-005 密钥管理。
- 建立 CI 或统一检查脚本。
- 生成完整 OpenAPI 文档。

验收：
- 干净环境按 README 可安装依赖。
- 前后端均有健康检查/启动页。
- 不需要 API Key 即可进入作品管理基础页面。
- `git status` 不包含数据库、密钥、用户小说数据。

## M1：作品与章节 CRUD

实现 novels / volumes / chapters、三栏骨架、revision 乐观锁。验收：T-001、T-002、T-004、T-014。

## M2：编辑器、自动保存与版本

canonical format、dirty/autosave、版本快照与恢复、Markdown/TXT 导出。验收：T-003、T-005、T-015。

## M3：模型配置与 AI 任务

model_configs、ai_tasks、OpenAI-compatible adapter、SSE、取消、候选采纳。验收：T-006–T-011、T-016。

## M4：设定与记忆

实体/事件/摘要/提案、上下文构建、stale 处理。验收：T-012、T-013。

## M5：创作质量工具

伏笔、冲突提示、选区改写、统计、评测样例。验收：伏笔按作品隔离且状态可更新；冲突检查只返回疑似冲突，不改正文或正式记忆；选区改写走现有任务，采纳前是候选，修订冲突返回 409；字数统计使用正文字数函数；固定评测样例可对模拟模型重复运行。

## M6：局域网部署与交付

Compose、认证、备份恢复、部署演练。验收：T-017、T-018。

## 给 AI 编程工具的总执行指令

1. 先检查仓库现状，不覆盖已有有效实现。
2. 一次只实施一个里程碑。
3. 先列文件与验收命令，再编码。
4. 不允许只做 UI 假数据。
5. 表变更必须附 Alembic migration。
6. 每个功能附自动化测试；外部模型用 mock adapter。
7. 不允许 AI 结果直接覆盖正式正文或自动写入正式记忆。
8. 不允许硬编码密钥、私有地址、真实小说内容或生产路径。
9. 完成后运行测试、类型检查、前端构建并报告真实输出。
10. 规范冲突时暂停说明，不擅自改核心架构。
11. 不要删除测试来使构建通过。
12. 交付含可运行代码、启动说明、变更摘要、测试结果和未完成事项。
