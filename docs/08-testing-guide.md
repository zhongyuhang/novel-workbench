# 08 测试与验收

## 1. 测试层次

- 单元测试：字数统计、上下文排序、状态迁移、版本号校验、提示词构造。
- 集成测试：API + SQLite、Alembic migration、模型适配器 mock。
- 前端组件测试：保存状态、错误提示、AI 候选采纳。
- E2E：创建小说、创建章节、写正文、AI 生成 mock、采纳、恢复版本、导出。
- 手工测试：不同浏览器窗口、局域网设备、备份恢复。

## 2. 必测验收矩阵

| ID | 场景 | 操作 | 预期 |
|---|---|---|---|
| T-001 | 新建小说 | 填标题并保存 | 列表出现作品，重启后仍存在 |
| T-002 | 章节编辑 | 输入多段正文并保存 | 正文完整保存，字数统计合理 |
| T-003 | 自动保存失败 | 模拟 API 失败 | 显示失败状态，文本仍留在编辑器 |
| T-004 | 版本冲突 | 两个客户端基于同一 revision 保存 | 第二次写入返回 409，不覆盖新内容 |
| T-005 | 版本恢复 | 恢复旧版本 | 新 revision 产生，旧版本仍保留 |
| T-006 | 模型未配置 | 点击 AI 续写 | 显示配置引导，不崩溃 |
| T-007 | 模型超时 | mock 超时 | 任务变为 failed，错误信息可理解 |
| T-008 | 流式完成 | 生成多个 token 事件 | 按顺序显示，完成事件只发生一次 |
| T-009 | 取消生成 | 生成中点击取消 | 状态变 cancelled，迟到 token 不写入正文 |
| T-010 | 候选采纳 | 生成候选并采纳 | 正文更新并创建版本 |
| T-011 | 候选拒绝 | 拒绝生成结果 | 正文不变 |
| T-012 | 记忆审核 | 拒绝提案 | 正式设定不变 |
| T-013 | 记忆来源 | 接受有证据提案 | 设定可追溯到章节和 revision |
| T-014 | 跨小说隔离 | 查询另一小说 ID | 不返回其他作品数据 |
| T-015 | 导出 | 导出多卷多章作品 | 顺序正确、正文无丢失 |
| T-016 | 密钥保护 | 查询配置、检查日志 | 不出现 API Key 明文 |
| T-020 | 模型配置 | 增删改、测试、默认、错误分类 | 用 mock 上游；无明文；变更后需重测；默认不可直接删除 |
| T-017 | 备份恢复 | 备份后新环境恢复 | 作品、章节、设定、版本可读 |
| T-018 | 局域网访问 | 从另一设备访问 | 可登录并使用；未认证访问被拒绝 |
| T-019 | 作品包 | 导出后导入为新作品 | 目录顺序一致；不覆盖原作；不支持的版本不写库；失败无半成品；包内无密钥 |
| T-021 | 引导式创意 | 回答引导后生成候选，忽略一份并确认另一份 | 忽略不改题材、设定和正文；确认后才写入作品信息或人物、世界设定 |
| T-022 | 编年史 | 手写事件，并用模拟模型生成规划后确认一份、忽略一份 | 视图按发生时间排列；忽略不写正式事件；确认后才写入；正文修订不变 |

T-017 与 T-018 的接口行为由 `backend/tests/test_m6_acceptance.py` 自动覆盖：备份后用 CLI 恢复到新的 SQLite 文件，再读取作品、章节、设定、版本和模型配置；配置了口令时，未认证请求返回 401，登录后可以访问。健康检查 `GET /api/v1/health` 保持公开，供本机和容器探针使用。另一台局域网设备上的浏览器登录是手工步骤，见 `docs/09-deployment-guide.md`。

## 3. 质量门槛

MVP 合并前：后端测试全部通过；前端类型检查和构建通过；关键用户流程 E2E 通过；无正文静默丢失；无高危密钥泄漏；迁移可从空数据库执行；README 启动步骤在干净环境验证通过。

## 4. AI 质量测试

不要求每次文本完全一致。要验证：结构化输出可解析；硬约束传入上下文；事实提取含证据；失败不污染正式数据；未采纳不改正文。

质量规则样例在 `backend/tests/fixtures/eval/quality_samples.json`。正例要有证据，反例不得报成冲突，无法比较的时间要标成证据不足。`pytest tests/test_quality_rules.py tests/test_quality_issues.py` 覆盖落库、差异预览、修订冲突不覆盖，以及已修复问题再次出现后回到待处理。

引导式创意、世界观和人物设计由 `backend/tests/test_ideation.py` 覆盖。模拟生成不访问网络。指定 `model_config_id` 时，mock 上游能看到这一份模型，省略时用默认模型，同一次会话再次生成不再换模型。回答未完成时不调用模型。忽略、延后和确认前都不改题材、实体、关系或章节修订。关系两端还不存在时确认失败。前端 `IdeationPanel.test.tsx` 覆盖模拟开始、确认、修改后确认、忽略和延后。

正文与资料同步由 `backend/tests/test_manuscript_sync.py` 覆盖。轻量检查不访问模型上游。完整分析用 mock 传输指定 `model_config_id`，省略时用测试成功后的默认模型。确认才写正式关系、伏笔和设定补充；忽略、延后不写。潜在冲突确认后只增加质量问题。影响分析只读。规则用例覆盖出生死亡、身份、死亡后的状态、世界规则、关系类型、伏笔的几个时间，以及暗线长时间未推进。前端 `MemoryPanel.test.tsx` 覆盖轻量检查和延后。

T-019 由 `backend/tests/test_e6_portable.py` 覆盖：往返后正文、大纲、设定、关系、事件、伏笔、摘要和版本仍属于新作品；第二次导入再得到一本新作品；格式版本 2 返回 `UNSUPPORTED_PACKAGE`；无效行与写入中途失败都不增加作品。前端 `LibraryMaintenance.test.tsx` 覆盖最近一次备份时间和导入预览。整库备份演练仍是 T-017。

E5 可靠性在 `backend/tests/test_e5_reliability.py`。它覆盖：并发保存和修订冲突不丢较新正文；手动保存、AI 采纳和质量修复采纳在快照失败时一起回滚；重复采纳和并发采纳只写一次正文；SSE 提前关闭后仍能读到候选；取消后的迟到 token 不改候选和正文；恢复旧版本不删除中间版本；版本详情和行级差异不改修订。迁移用例确认从 `0009_quality_issues` 升级后旧快照仍在，新外键可空，降级后列消失。前端 `saveResult.test.ts`、`textDiff.test.ts`、`taskRecovery.test.ts` 以及编辑器和 AI 面板测试覆盖迟到保存响应、冲突比较、断线回查和取消失败后的任务状态。
