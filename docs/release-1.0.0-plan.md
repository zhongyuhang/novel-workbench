# release 1.0.0 方案

个人长篇小说 AI 创作工作台。浏览器访问，部署在个人服务器或局域网。作者做决定，AI 辅助生成、提取、整理和检查。正文、人物、世界观、编年史、剧情线和伏笔互相可追溯。部署者自己配置大模型，不绑定厂商。

本方案在已有实现上补齐，不推倒重写，也不更换技术栈。

## 要做

- 作品、卷、章节管理
- 正文编辑、自动保存、版本和导出
- 引导式创意，以及世界观和人物设计
- 故事大纲、编年史、主线、暗线和伏笔
- AI 续写、扩写、润色、改写和规划辅助
- 候选先审阅，确认后才进入正文
- 人物、事件、关系和线索的增量提取
- 资料与正文关联、追溯和一致性检查
- 模型配置中心：增删改、测试、选择和切换
- 登录、密钥加密、备份与恢复
- 自动化测试、部署文档和可执行验收

## 不做

多租户、注册、协作和计费。向量库和复杂检索。多 Agent。训练微调。自动发布。原生 App。模型市场和用量计费。

## 技术基线

React、TypeScript、Vite。FastAPI。SQLAlchemy 2。SQLite。Alembic。Tiptap JSON 为正文权威格式。统一的 OpenAI 兼容适配层。SSE。Fernet。Docker Compose 与 Caddy。数据放在 `DATA_DIR`。

## 模型配置中心

部署者在网页里配置模型，不改源码，也不重新构建。

设置里有独立的模型配置页：列表、新增、编辑、删除、测试连接、设为默认，并显示当前默认和测试结果。AI 创作界面可以切换这一次任务使用的模型。

列表显示名称、服务商、模型标识、Base URL、状态（未测试、成功、失败、配置已变更）和默认标记。不返回明文密钥。

表单必填名称、接口类型、Base URL、模型标识和 API Key。接口优先使用 OpenAI 兼容 Chat Completions。可选服务商预设、超时、默认温度、默认最大输出和自定义 Header。

服务商预设提供 OpenAI、DeepSeek、通义千问兼容、智谱兼容、Moonshot / Kimi 兼容和自定义。预设只给默认地址和提示，用数据驱动，不写成页面里的白名单。用户改过的 Base URL 必须保留。不假定各模型能力相同。也可以直接填写自定义的兼容地址。

测试连接先校验必填、地址格式和安全策略，再发一条真实的最小请求，核对鉴权、模型和响应格式。成功时显示模型标识、耗时和必要的响应信息。失败分为：密钥缺失或鉴权失败、Base URL 错误、模型不存在或无权、限流、网络失败、超时、响应不兼容。不能只判断响应非空，也不能泄露密钥。

默认模型：需要至少一份可用配置。只有测试成功的配置可以设为默认。任务默认用它，也可以临时换一份；任务开始后固定所用配置。删除默认模型前必须先另选，不能留下无效默认。历史任务记录模型标识和配置 ID。不做自动路由、负载均衡或故障切换。

## 数据与安全

模型配置至少保存标识、名称、服务商、接口类型、Base URL、模型标识、加密后的 API Key 和自定义 Header、超时、默认温度、默认最大输出、是否默认、最近测试状态、测试时间、测试错误码，以及创建和更新时间。命名沿用现有表风格。

用 Fernet 加密。主密钥放在独立环境变量。缺失或无效时启动失败并写明原因，不得改存明文。

查询只返回是否已配置密钥。编辑时密钥留空表示保持，填入新值才替换，并提供明确的清除操作。删除配置时同时删除凭据。日志不记录密钥和 Authorization。备份包含密文，恢复后用同一主密钥解密。主密钥要单独保存，丢失后原密文不能恢复。

Base URL、模型、密钥或关键参数变化后，测试状态变为「配置已变更，需重新测试」。

服务端拒绝回环、内网管理和云元数据地址，限制重定向。本地模型用部署级允许名单放行。不能只靠前端拦截。

## 接口与统一调用

配置接口覆盖列表、创建、读取、更新、删除、测试和设为默认。全部经过登录。保证最多一个默认。错误结构不返回堆栈或凭据。删除默认时拒绝。服务端可以保留脱敏后的诊断。

调用路径是：业务模块到 AI 服务层，再到配置解析，再到 OpenAI 兼容适配器，最后到上游。这一层读取本次选定的配置、解密密钥、组装参数、处理超时和错误、支持非流式和 SSE、记录调用元数据，并处理连接、限流、超时和格式异常。不泄露密钥和正文里的敏感内容。厂商特有参数只在该配置支持时发送。所有 AI 功能都走这一层，不在各模块里硬编码厂商地址。

创意引导、世界观和人物设计、故事大纲、编年史和事件规划、主线暗线伏笔规划、正文续写、润色改写扩写、正文增量提取、一致性检查和资料整理，都用 `model_config_id` 指定模型。缺省用系统默认模型。

## 正文与资料

采用「AI 识别、作者确认、系统持续校验」。对象包括世界设定、人物及关系、编年史与事件、主线支线暗线、伏笔与线索、章节与场景。

作者可以主动触发。章节完成时做完整分析。保存或修改后可以做轻量检查，不要求每次自动保存都调用大模型。

候选包括新实体、事件、状态变化、关系变化、线索伏笔、设定补充和潜在冲突。每条带来源章节和原文证据，并与正式资料分开存放。

审核动作：确认、修改后确认、忽略、延后、标记为有意安排的矛盾。确认之后才更新正式资料。

一致性检查至少覆盖出生与死亡及事件时间、身份经历、状态变化、世界规则、人物关系和暗线推进及伏笔回收。结果区分为确定性错误、疑似矛盾和创作风险。

伏笔的时间分开记录：事件实际发生时间、正文埋设位置、角色发现时间、向读者揭示时间、最终回收状态。不能压成一个日期。

已确认的设定被修改后，要能找出受影响的对象。

## 生成闭环

选择作品、章节和任务，组装上下文，选择模型（默认用系统默认），生成候选并流式展示，审阅修改后确认，写入正文并建立版本，再按需提取资料候选，并对受影响资料做一致性检查。

任务包括续写、润色、改写、扩写、大纲生成，以及人物和世界观辅助设计。未确认的结果不得写入正文或正式资料。

## 备份、部署与验收

持久化作品、正文、人物、设定、编年史、伏笔、模型配置和必要的审计信息。正文以 JSON 为权威。版本可追溯。使用 `DATA_DIR` 和 Alembic。

备份包含作品数据和模型配置密文。恢复时检查备份完整性，并做基本可用性检查。文档写明主密钥必须单独保存。

部署验收：按文档配置环境变量，启动并迁移，打开网页，首次登录，配置并测试模型，创建作品并完成一次 AI 生成，重启后作品和模型配置仍在。

## 测试与发布

模型配置测试覆盖增删改、默认、用 mock 上游做的真实请求形状、错误分类、响应无明文、加密持久化、编辑其他字段不清空密钥、关键变更使测试失效、删除默认保护、流式输出、超时限流和网络异常，以及模型选择传到各个 AI 模块。不依赖收费模型。真实连接测试留在部署验收。

创作测试覆盖作品卷章、自动保存、版本比较和恢复、候选不覆盖正文、资料候选含证据和来源、确认才更新、修改设定后识别受影响对象、一致性检查、伏笔埋设揭示和回收，以及导出正文和必要资料。

后端用 pytest，前端用 Vitest。

发布时：能按文档启动；用户能自己配置并测试模型；更换模型不改源码、不重建前端；AI 功能走统一调用层；作品、正文和资料能持久化；AI 结果可审阅、确认和追溯；正文与资料能做基本同步和一致性检查；密钥安全；备份恢复已验证；自动化测试通过。
